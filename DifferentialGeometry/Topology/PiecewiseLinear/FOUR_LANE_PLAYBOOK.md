# 四车道协作方式（2026-09-17 至 09-18 的实际做法，写给 Codex）

这份文件讲**怎么运作**，不讲数学状态；数学状态在 `HANDOFF_CODEX_INTEGRATION.md`，主链与决定在 `MOISE_CHAIN.md`。
所有内容都来自这两天实际发生的事，包括失误。

## 0. 一句话

一个**整合者**加**四条车道**（F、H、E3、S）。每条车道独占一个工作树、一个分支、一个 HANDOFF 文件；
车道之间**只通过整合分支**看到彼此；整合者不写主线 Lean，只做派工、核验、合并、记录、拍板。
两天里整合分支收了约 210 个提交、80 多个新模块、1.4 万行以上，每个模块在原车道和整合分支各编译一次。

## 1. 角色与边界

| 角色 | 工作树 / 分支 | 职责 |
|---|---|---|
| F | `D:\differential-geometry-moise-plan` / `codex/moise-smoothing` | PL 基础、图卡、正规形式、顶点层与链层 |
| H | `…-moise-h` / `codex/moise-h` | 同调与曲面 → 后转为球对、正则邻域、弧链 |
| E3 | `…-moise-e3` / `codex/moise-e3` | §25.1 的终局：分支分离、切贴、复杂度下降 |
| S | `…-moise-s` / `codex/moise-s` | Schoenflies 输入、CST 的 C.6 三项义务、定向 |
| 整合 | `…-moise-int` / `codex/moise-integration` | 派工、核验、合并、`MOISE_CHAIN.md`、决定 |
| 专用 | `…-moise-hw`、`…-moise-t` | 高风险操作各开一个分支（见 §7） |

**文件所有权**：新模块归创建它的车道；不改别人的模块；要改共享的老模块（无车道占用）先问整合者，
且改动只能**加强结论**并重编全部消费者（注意 `obtain ⟨…⟩` 定长模式会因多一个合取项而断，见 §5）。
共享 olean 库 `E:\differential-geometry-dev\.lake\build\lib\lean` 只由 `check-f.ps1` 写；同一模块同一时刻只在一个工作树编译。

**主机资源**：`lean.exe` 全机 ≤ 4；每个 agent ≤ 1；六个 agent 同时跑时，每次编译前 `Get-Process lean` 计数、≥ 4 则等。

## 2. 一轮（round）的节奏

1. **派工**（整合者 → 车道）：任务书见 §3。
2. **车道干活**，固定顺序：`git fetch && git merge --no-edit origin/codex/moise-integration` →
   读自己 HANDOFF 末几节与对方接口 → **先 grep 再建** → 写 → `check-f.ps1`（exit=0、零 warning）→
   `audit-f.ps1`（只含 `propext`/`Classical.choice`/`Quot.sound`）→ 一个闭合结果一个提交 → HANDOFF 加一节 → push → 报告。
3. **报告格式**（固定）：定理名、exit code 与秒数、审计计数、**确切剩余义务**；不报未测的行数估计（"未开始、无估计"是合格答复）。
4. **整合者独立核验**（不接受口头）：分支干净、与远端 0/0、对新文件 grep 禁用记号（`sorry|axiom|nolint|maxHeartbeats|set_option|--|/-`）、
   **在整合工作树重编每个新模块**、必要时自己写跨 import 的 scratch 做 `#print axioms`。
5. **合并、推送、记录**：`MOISE_CHAIN.md` 只记三类东西——决定、更正、负面结果（负面结果单独标题、写出坐标论证）。
6. **下一轮派工**时带上其他车道**最新**的接口形状（今天接口改了三次：源侧→像侧契约、单平面→板状边界、滑动→楔推）。

一轮通常 15–60 分钟；两天里每条车道跑了 8–12 轮。

## 3. 任务书模板（每次都完整重发，agent 是无状态的）

1. 硬规则块（零注释/零 docstring/无 sorry 等；不推 main；不写 `E:\`；不进根聚合；不 import 含 `sorry` 的文件；
   未完成依赖写显式假设；一个结果一个提交；提交信息英文一句数学结果 + 署名行；≤1 个 `lean.exe`；先 merge 整合分支；做完 push）。
2. **上下文**：别的车道刚交付了什么、接口现在是什么形状、哪个前提已被证伪。
3. **任务**：按顺序、每项可单独提交；写明"在第一个不落地的地方停下报告，说清障碍与证据"。
4. **先做的检查**：先 grep（按内容、数命中、看构造）；先构造一个满足全部假设的实例；再证。
5. **所有权清单**：不许改的模块按车道列出（今天一次同名文件冲突、一次同名定理冲突都来自漏列）。

## 4. 整合者每次合并前的清单

- `git status` 干净；`git rev-list --count origin/<lane>..HEAD` 与反向均为 0。
- 新文件 grep 禁用记号。
- 在整合工作树 `check-f.ps1 -Module …` 重编**每个**新模块（不是抽查）——两次抓到共享 olean 被污染：
  一次是车道改名前已编、同路径被另一车道的文件占据；一次是合并后旧 olean 对应新源码。规则：**改名前先编，合并后重编。**
- 涉及多车道声明时写一个同时 import 它们的 scratch 跑 `#print axioms`（抓重名与 `sorry` 渗入）。
- 合并后立刻 push；记录到 `MOISE_CHAIN.md`。
- 车道分支与整合分支互相合过之后，各车道应与整合分支 0/0（每日收尾检查一次）。

## 5. 今天抓到的失效类型，以及对应的检查

这是最有价值的一节。每一条都发生过，多数由车道**自己**抓出来。

| 失效 | 实例 | 对应检查（写成"第一个动作"） |
|---|---|---|
| 搜索范围错 | H 只搜 PL 子树报"无同痕"；整合者扩大为全树；E3 报 `CutAndPaste.lean` 不存在（在子目录） | 按内容 grep，**词汇包括文件名与目录** |
| 失败的 grep 当不存在 | S 的 grep 退出码 2、空输出，据此把已存在的一整层估成新工程 | **非零退出的空输出不是证据** |
| 截断的结果 | F 用 `head -4` 只看到四个子串命中，差点发假更正；去掉 `head` 有 57 条 | **先数命中数再读** |
| 从名字推性质 | "radialProj 是径向的所以保持锥"（实际只在顶点径向、面上仿射插值）；"非退化 = 不共线"（实际是径向单射性，且不共线对 `C₂` 为**假**） | **看构造不看标识符**；看引理证了什么而不是它关于什么 |
| 同名声明 | H 的 `exists_isPLHomeomorphOn_closedStar_pair` 与 `StarPair.lean:78` 重名，且更弱；H 自己模块 import 不到对方所以聚焦检查通过 | 新声明（**含 `def`**）前全树 grep；跨 import 审计 |
| 空 / 不可满足的陈述 | `hgen`（等价于结论）、`IsGeneratedByPolygon` 在 ℕ 上不可满足、`hJoff` 强迫空交、`hfiber` 对盘形片恒假、§46–§73 边界滑动链无实例、F 打包定理契约藏在存在量词内 | 三项审计：假设标注几何输入/构造产物；**在目标实例中可满足**；`∃ x, … ∧ (hyp x → …)` 时消费者能否给出 `hyp x`；**证前先造一个实例** |
| 定义扛着只有生产者需要的条件 | `IsPLBallPair` 三次改（锥形→PL 同胚存在；面包含→集合包含；M2 也带着子复形条件） | 假设放在**被用的地方**，不是写着方便的地方 |
| 包装丢掉证明里已有的东西 | `ConeAmbientExtension` 内证相对条款又丢；`PLImage.lean:113` vs `:140`、vs `AffineImageTransport.lean:13` 各丢一半；F 两次用 `-` 丢掉后来要用的分量 | **先提取再往上建**；解构模式里的 `-` 处二看 |
| 估计系统性偏高 | 弧邻域是球：估 1k–2k、实 227；任意余维 starring：估 0.5k–1.5k、实 ~20；PL 搬运：估 200–500、实 40；棱柱：估 400–900、实 296 | 不报未测估计；估之前先 grep |
| 参数化选错 | 直线插值是二次的/双线性的（非 PL）三次出现；改按高度参数化、改拆两个三角形 | 先问"这个表达式是否是两个非常值 PA 函数之积" |
| 整合者的错误 | 把源侧契约转给 H（形状错）；"径向保持锥"；给错 Mathlib 文件；"树里无同痕"；"加合取不破坏消费者"（`obtain` 定长会断）；让 E3 重做已存在的 `L₁`；把"折片"观察张冠李戴给 E3 | 整合者也要被核验；**车道纠正整合者是常态，应被鼓励并记录** |

一条通用观察：**规则写成"关于世界的事实"是死的，写成"某情境下的第一个动作"才管用**——
"import 可能导致 unknown identifier"没用，"遇到 unknown identifier 先查 import"有用（H 记下前者后一轮又撞同一个坑）。

## 6. 车道换人

**信号**：agent 自报"判断仍准、执行变慢"（一条引理编译八次都是实例摩擦）；连续两轮只交报告不交 Lean；
自己违反自己刚写下的规则。H、E3、S、F 四条车道今天都出现过，都是 agent 主动提的。

**做法**：让旧 agent 把 HANDOFF 写成**可独立执行的规格**（每个引理名、方向、file:line 都核过）；
新 agent 以该规格为唯一输入，任务书里带上 §5 的全部纪律；新 agent 第一轮通常比旧 agent 最后几轮快得多。
**不要**让疲劳的 agent 硬开一个大块（留半截比不开更糟）。

## 7. 高风险操作用专用分支

与 `pc-sorry-free` 合并、30.5 的 tame 版本，都各开一个工作树和分支，满足写明的合入条件才并入整合分支。
派工前整合者**先实测代价**（merge-base、双侧改动文件数、dry-run 冲突数），把数字写进任务书，不让 agent 自己猜。
只读的可行性核查（30.5 是否需要 wild 胞腔）单独派一个不写 Lean 的 agent；结论落地后再让**同一个** agent 转为建造，因为它手里有 file:line 地图。

## 8. 记录纪律

- `MOISE_CHAIN.md`：决定、更正、负面结果；每条带日期与理由。负面结果要写到别人**不会再走一遍**的程度（坐标、反例）。
- 各车道 `HANDOFF_CODEX_*.md`：编号节；每节含交付、验证数字、失败路线、陷阱、确切剩余义务；末节"中断时状态"。
- 提交信息：英文一句话说数学结果，正文说数学内容，不写文件名、不写 "add"；末行署名反映**实际生成提交的模型**。
- 审计文件放 `.lake/scratch/`，按车道编号（`AuditF282.lean` 等），报告里给计数。

## 9. 建议 Codex 保留与改变

**保留**：§2 的节奏、§3 的模板、§4 的清单、§5 的检查、§6 的换人、§7 的专用分支。

**改变**：
1. 整合者派工前**自己先 grep 一次**——今天至少两次让车道去做已经存在的事（`L₁`、`isPLHomeomorphOn_simplicialMap_radialProj_…`）。
2. 把"先造一个满足全部假设的实例"**前置到任务书**，不要等审计；今天三个空陈述都能被它提前挡住。
3. 每十轮左右做一次**可行性复盘**（读计划、读链表、数一数哪些结点卡在决定而非数学）；今天做了一次就发现三个决策阻塞，
   其中 30.5 的 10k–18k 估计被一轮只读核查缩到 1k–2k。
4. 接口一旦改形状，**当轮**通知所有消费方并写进任务书；今天像侧契约、板状边界两次改动都及时传了，但源侧契约曾被错误地传了一轮。
